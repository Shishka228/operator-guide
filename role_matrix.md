# Матрица ролей учебного сервиса заявок (SPEC-1.0, интерфейс 1.5.0)

Все данные синтетические. Матрица описывает только целевые роли руководства — оператора и техника. Административные роли вынесены за пределы руководства (см. раздел «Вне руководства»).

**Источники:**
- `data/service_spec.md` — SPEC-1.0 (права, лимиты, статусы).
- `data/operator_observations.md` — наблюдения интерфейса 1.5.0.
- Figma-макет «Учебный сервис заявок • оператор и техник», node-id 3-371 — визуальная сверка кнопок, полей и состояний.


## 1. Целевые роли

| Действие | `operator_a` / `operator_b` (оператор) | `technician_a` (техник) |
|---|---|---|
| Видеть список заявок | Только свои (фильтр «Мои») | Только назначенные (фильтр «Назначенные») |
| Создать заявку | Да, экран «Новая заявка», кнопка «Создать» в правом верхнем углу списка | Нет |
| Читать карточку | Только собственную | Только назначенную |
| Редактировать заявку | Только собственную открытую (`open`) | Нет |
| Прикладывать файлы | Да, 0–3 файла PDF/PNG, каждый ≤ 5 000 000 байт, пустой не принимается, проверяется фактический тип содержимого | Нет |
| Перевести `open` → `in_progress` | Нет | Да, кнопка «В работу» под описанием |
| Перевести `in_progress` → `resolved` | Нет | Да, кнопка «Отметить выполненной»; **неактивна, пока поле «Комментарий исполнителя» пустое**; комментарий обязателен |
| Удалить заявку | Нет | Нет (кнопки удаления нет) |
| Видеть чужие заявки | Нет: «Нет доступа к этой заявке» в красной рамке | Нет: видит только назначенные |
| Обходить ограничение доступа | Запрещено; при отказе — ссылка «К списку» | Запрещено |



## 2. Визуальные признаки состояний (по Figma, node 3-371)

| Элемент | Как выглядит | Что означает для читателя |
|---|---|---|
| Статус `open` | Нейтральный бейдж | Заявка создана, ждёт исполнителя |
| Статус `in_progress` | Оранжевый бейдж | Техник нажал «В работу» |
| Статус `resolved` | Зелёный бейдж | Техник завершил с комментарием |
| Успех создания | Зелёная плашка «Заявка LAB-104 создана» + ссылка «Открыть» | Заявка сохранена, номер присвоен |
| Отказ: 4-й файл | Красная плашка «Можно приложить не более 3 файлов» | Текст остаётся в форме, нужно убрать лишний файл |
| Отказ: сеть | Жёлтая плашка «Не удалось получить ответ. Проверьте список заявок перед повтором» | Операция могла сохраниться — сначала проверка списка |
| Отказ: доступ | Красная рамка «Нет доступа к этой заявке» + ссылка «К списку» | Закрытые сведения не показываются, обход запрещён |
| Кнопка «Отметить выполненной» | Серая (неактивна), пока комментарий пуст | Нельзя завершить заявку без комментария |



## 3. Ограничения, важные для текста руководства

- Доступ ограничивается сервером; отсутствие кнопки само по себе не является проверкой полномочий. Поэтому в руководстве не предлагается «искать обходной путь».
- Повтор запроса с тем же `idempotency_key` и тем же содержимым не создаёт вторую запись; при изменённом содержимом и том же ключе — конфликт без новой записи.
- После сетевого тайм-аута сначала проверяется список: операция могла сохраниться.
- Допустимые статусы: `open`, `in_progress`, `resolved`. Переход в `resolved` требует непустого комментария исполнителя.
- Нажатие «Отправить» не доказывает сохранение: нужен номер и повторное открытие заявки.



## 4. Вне руководства (административные действия)

`manager_a` (чтение всех заявок, назначение исполнителя), развёртывание, миграция M015, резервное копирование, передача секретов — не входят в руководство оператора и техника. Для этих действий предусмотрено обращение в поддержку. Отсутствие административных кнопок на экранах оператора/техника — норма, а не ошибка интерфейса.



## 5. Словарь терминов (5 терминов интерфейса)

| Термин | Определение, помогающее выполнить действие |
|---|---|
| Заявка | Запись с темой, описанием, статусом и вложениями; создаётся на экране «Новая заявка» и открывается из списка. |
| Номер | Идентификатор конкретной записи (например, `LAB-104`); используется для поиска и повторного открытия именно этой заявки. Номером кабинета или телефона его заменять нельзя. |
| Статус | Текущее состояние заявки: `open`, `in_progress`, `resolved`. По бейджу статуса видно, на каком шаге обработки находится заявка. |
| Вложение | Файл PDF или PNG, приложенный к заявке (не более 3 файлов, каждый ≤ 5 000 000 байт). Нужен, чтобы передать изображение или документ вместе с описанием. |
| Исполнитель | Сотрудник, которому назначена заявка (например, `technician_a`). Исполнитель переводит заявку в работу и завершает её с комментарием. |
