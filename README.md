# Практическая работа 16. Разработка руководства оператора

Учебный сервис заявок, интерфейс **1.5.0**, спецификация **SPEC-1.0**.
Все данные синтетические. Скриншоты не имитируются.

## Источники
- `data/service_spec.md` — SPEC-1.0 (бизнес-правила, лимиты, роли).
- `data/operator_observations.md` — наблюдения интерфейса 1.5.0.
- **Figma-макет** «Учебный сервис заявок • оператор и техник», node-id 3-371:
  https://www.figma.com/design/RjTPhmlThjW9P0F0IAoEEQ/...?node-id=3-371
  Использован для визуальной сверки кнопок, полей и состояний.

## Аудитория руководства
- оператор (`operator_a` / `operator_b`) — создаёт и проверяет свои заявки;
- техник (`technician_a`) — работает с назначенными заявками.

Административные действия (назначение исполнителя, развёртывание, миграции)
в руководство не входят — для них предусмотрено обращение в поддержку.

## Краткий словарь

| Термин | Определение, помогающее действию |
|---|---|
| Заявка | Запись с темой, описанием, статусом и вложениями. Создаётся на экране «Новая заявка», открывается из списка «Заявки». |
| Номер | Идентификатор конкретной записи, например `LAB-104`. Нужен для поиска и повторного открытия заявки. Не заменяйте номер номером кабинета, телефона или другой служебной записью. |
| Статус | Состояние заявки: `open` — создана, `in_progress` — в работе, `resolved` — выполнена. По статусу проверяют этап работы. |
| Вложение | Файл PDF или PNG, приложенный к заявке. Допускается не более 3 файлов, каждый не более 5 000 000 байтов; пустой файл не принимается. |
| Исполнитель | Сотрудник, которому назначена заявка. Техник видит только назначенные ему заявки; в карточке отображается исполнитель. |
